# Phota 精进路线图：更准、更专业有创意、用更少指导出片

修订：2026-10-27，替代 2026-10-24 版，保留原文件名。

本次只修订计划和制定 [评分细则 v2](../../evaluations/phota-scoring-v2.md)。不代表第 0 阶段已完成，不据此自动开始应用开发、采集、接口调用、评测、APK 打包或 Git 提交。

后续授权记录：用户已要求执行第0阶段，允许本阶段的规则登记、工具、冻结基线和已有公开案例推理评测。阶段1–5仍未启动；下文“本次”文档修订的范围说明保留为历史，不能用来否定后续明确授权。

## 目标与边界

让摄影师和模特获得准确、能执行、与现场有关的指导，用尽量少的动作改善成片。没有值得调整的问题时，允许保持原片、直接拍摄。

提升手段限于提示与流程、程序计算、专业知识库和真实拍摄评测。**禁止微调、蒸馏、教师答案训练及其他权重训练，不设置未来重新考虑权重训练的阶段。** 用户批注用于评价，不把某张照片的答案硬写进通用提示。

主线是单人出片。普通指导、深度分析分别报告；多人、宠物、食物和风景不作为单人出片的必达采集配额，扩展范围另列任务。

私人照片在 App 中联网指导与导出后再次发送给模型做研究评测是不同用途。开启本地记录不等于授权外传，研究评测须取得本批明确授权。公开案例记录作者、出处、许可和核验状态，不推定公开即获再分发许可。

不打包 APK。记录功能可先在浏览器开发验证；要让手机安装版具备新功能通常需要更新，但必须按用户后续指令处理。未更新不得说手机已能自动记录。评测记录不自动上传。

## 历史出发点

截至 2026-10-24 的报告：正式出片提示为 v16，v21 未晋级；9 位新手作者均已曝光；已有 4:3/16:9 取景输入、身份锁、盲选页和用量账本。最近报告记录 110 项单元测试与 81 个布局检查通过，**本次没有重跑**。

已知短板：花枝压头发有局部改善，但仍存在“脸坐标居中、文字说贴边”、误调/漏调和道具互动不可靠。尚无经核验的真实指导前后记录，不能声称实际成片改善、单步有效率或真实出片步数。

## 预设验收目标

分母、独立样本、缺失和失败按评分细则执行。下面是目标，不是已取得的成绩。

| 指标 | 准确性检查点 | 完整候选晋级目标 |
| --- | --- | --- |
| 最终展示或驱动行为的硬错误 | 本批为0，未决疑点须解决 | 最终检查为0；完全拦截的内部错另报，不宣称总体错误概率为零 |
| 不必要调整率 | ≤20% | ≤15% |
| 漏调率 | ≤25% | ≤20% |
| 严格出片成功率 | 实拍建立基线 | 不低于匹配v16，完整报告弃拍和未完成 |
| 成功拍法调整步数（独立动作数） | 等待真实数据 | 中位数≤2、平均≤2.5，同时报告成功率与交互条数 |
| 单步有效率 | 第3阶段≥60% | ≥70%，并报告执行覆盖率 |
| 实拍成片四维专业分 | 与建议适配分分开 | 配对组均差≥+0.5/5，任一维平均不下降 |
| 冻结新版盲评偏好 | 小批只作反馈 | 决胜独立单位≥30、观测胜率≥60%、95% Wilson下限>50% |
| 不适用建议/违背保留意图 | 建立单版本人工基线 | 两项均不高于匹配v16；另报A/B“都不好/原片最好” |
| 现场关联率 | 建立基线 | ≥90%；保持原片单列，不强迫添加互动 |
| 效率 | 全流程记录 | 全批最终可用率≥95%、等待中位数≤5秒，平均估算费用≤¥0.03/有效指导；失败等待按∞纳入，另报P90及后台成本 |

≥30只是最低样本门槛，不保证统计通过。不同候选不能拼成绩。有限样本零错误只能表述为本批未发现。缺失值不按0或默认通过补齐。

## 阶段与依赖

允许并行准备，未过验收不得替换正式版。第0阶段后，本地记录和可静态验证的准确性任务并行，不等实拍采满。

### 第0阶段：规则与基线

- [x] 制定评分细则v2文档：硬错、分母、专业分锚点、盲评与真实效果口径。此勾选只表示文档已制定。
- [ ] 评测启动前登记冻结：规则SHA256、案例清单、输入/版本、计划次数和停止条件；改规则须升版，不回改旧分帮助过关。
- [ ] 按作者、人物、拍摄组关联隔离开发/回归/封存数据。现有9位作者不能恢复封存身份；回归结果若用于改方案，登记开发曝光。
- [ ] 实现文字与坐标一致性检查；启发式报警交人工核验，不当真值。
- [ ] 固定验证清单：按变更跑对应单元/API、布局、语音；晋级前完整相关回归。文档改动不触发应用测试。
- [ ] 运行冻结v16基线：静态先测事实、需求判断、预计适配、关联、延迟/费用；实拍有效率、步数、成片提升明确写“暂无数据”。

通过条件：规则与分组冻结、可测基线和缺失项有报告、封存未污染。本次不执行以上未勾选任务。

### 第1阶段：本地记录与持续实拍

- [ ] 默认关闭的本地记录：前帧、最终原样指令、后帧、时间、版本、画幅、拍法/步骤ID、是否照做、快门与评价。
- [ ] 手动导出/导入并验证来源。不自动上传；重发模型研究须本批授权。手机未更新时可手工留图/指令截图，标手工来源与缺失项。
- [ ] 主要流程：Phota指导前留帧 → 记录Phota原话 → 照做后留帧 → 更好/一样/更差/无法判断。用户自创或改写指令单列，不混算Phota效果。
- [ ] 先做1–2次流程试拍，核验记录完整性，列入开发数据。
- [ ] 第一轮检查点：至少10次会话、40组有效前后照片。每周2–3次约需4–5周，不再承诺2–3周。
- [ ] 第一轮累计至少3类条件（窗光、户外顺光、逆光、阴天、夜景中选），包含“保留即可”和“值得调整”。每次只拍一处也可以。
- [ ] 持续目标：30次会话、100组，按同频率约需10–15周。扩展至五类光线及不同环境，报告真实数量，不重复凑配额。
- [ ] 持续补充公开新作者用于独立检查；新手身份不确定就注明。数据管理员可预标注封存照片，但开发者不能用其调方案。

第一轮只说明可开展实拍诊断，不证明泛化或最终达标。效果晋级仍需冻结候选的匹配实拍对照和独立偏好证据。时间不足调整进度，不隐性提高用户拍摄频率。

### 第2阶段：准确性

第0阶段后与记录工具并行，优先前两项。

- [ ] 模型报坐标/框，可计算描述由程序生成；这只解决数值与文字一致，框是否准确仍须核验。
- [ ] 歪斜、切边先检测候选问题，再结合透视、主体及明确意图核验，不把斜线、贴框直接判坏。
- [ ] 每项问题引用可追溯证据。坐标能说明位置，不能单独证明必须移到三分线；信息不明不臆造。
- [ ] 建立保留原片案例：暗调、留白、散景、严肃、不对称、刻意裁切。作者明确意图优先，模型推测只作假设。
- [ ] 新实拍到位后检验误调/漏调，普通指导与深度分析分表。

通过条件：达到本阶段目标，标注完整，无未决硬错；冻结候选后一次封存确认。缺实拍指标不能声明整体晋级。

### 第3阶段：减少无效步骤

- [ ] 先给证据充分、收益大、能执行、下一帧能核验的一项；优先级结合意图，不机械固定。
- [ ] 默认一个可核验调整。主验收步数按独立动作计，一条含k个独立动作计k步，交互条数另报，不能通过捆绑动作刷少步骤。
- [ ] 够好就拍；同拍法最多4个独立调整动作。连续两次已执行指导未改善时停止折腾或换法，仍有硬问题不能谎称已达标。
- [ ] 核验执行、目标和新增问题；已完成不重复，没完成先查原因。
- [ ] 回放仅验证已有路径。新指令没有对应执行后图时不能算效果，须补真实对照。

通过条件：成功拍法步数中位数≤2、单步有效率≥60%，不必要调整率不升，严格出片成功率不降；完整披露未执行与未完成。

### 第4阶段：专业与创意

- [ ] 光线、姿态、构图、环境拍法手册注明适用条件、证据、限制及来源，按现场检索。
- [ ] 从1个候选测质量/耗时，再试2个；有收益且预算允许再试3个/额外评审，不预设固定倍数。
- [ ] 可预计算，但场景/人物/道具/意图变化须失效；换法前复核适用性，后台废弃调用计费。
- [ ] 道具按可达、已持有、抬起、互动逐步核验，不跳前提；每步有失败处理。
- [ ] 风格为可选偏好，不把推测当用户意图。

通过条件：准确性、实拍成片、独立盲评和效率同时达到完整晋级目标。未过延迟就减候选/简化/继续实验，不能用后台计算隐瞒成本。

### 第5阶段：个人偏好，后续可选

- [ ] 本地偏好可查看/清除，区分个人喜欢与通用原则。
- [ ] 按熟练度调整说法，动作数量须有依据，不随口编厘米。

通过条件：个人匹配对照的满意度与有效率改善、硬错误不增加；不推广为所有用户结论。

## 每轮评测和封存

1. 只用登记开发案例修改候选；正式版不动，失败原因留档。
2. 冻结提示/实现、模型、规则、输入、案例、运行次数与停止条件。
3. 相关回归有最终展示或驱动行为的确认/未决硬错，不进入晋级；完全拦截且未使用的内部错误另报。
4. 同一冻结候选可每批3–6组盲选；改候选后重新累计。相同作者、照片或画幅不冒充新独立样本。
5. 封存批次预登记，可分次评阅，但结束前不根据中途成绩改方案或提前停在有利数字。用过降为回归，再补新组。
6. 样本不足只报初步；匹配输入/条件比较v16，不反复查看统计结果直到凑出显著。
7. 同时报告都不好、原片最好、失败、缺失、弃拍、未执行与全部调用。偏好胜出不替代成片改善证据。

## 时间、费用与分工

取消固定10周完成的承诺。第0阶段/工具工期待开工拆分；首轮实拍4–5周、持续目标10–15周，从实际开始拍摄算起，准确性工作可并行。阶段晋级由证据决定。

用户按自己的节奏实拍并评价，参与少量盲选；助手负责工具、规则实现、样本登记、评测和报告。当前按后续指令仅执行第0阶段，不自动进入后续阶段。

未来预算按案例数×版本数×重复次数×实际阶段调用数，加失败/修复/候选/后台开销计算；以最新返回用量估算并与账单区分。没有运行清单，不承诺第0阶段只花¥1–2，不沿用未经本次核验的总账数字。5秒和¥0.03是验收目标，不是保证。
