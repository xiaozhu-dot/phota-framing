# 实际取景输入下的出片回归：4:3 / 16:9

本轮 v21 在持花案例的两种画幅中均识别到头发与前景花枝重叠，并给出降低手机位置、保持朝向再复看的指令。正式 v16 两次均漏掉此问题。但 v21 对海边图两次都把中央的脸描述为贴边，并据此要求视线留白调整，不能整体晋级。正式提示仍为 v16，字节对比与冻结副本一致。

## 输入与方法

`eval/portrait_frames.mjs` 在本地 Chrome 中调用应用原有 `createCamera.frame(1024,0)` 和 `toDataURL(canvas,.86)`，生成中心裁切及 JPEG 输入。固定 1×、quarter=0、无 PRO 模拟滤镜。独立 800×1600 彩色条带验证 4:3 裁去上下端、16:9 保留上下端，并检查尺寸及 JPEG 类型。

| 案例 | 4:3 输入 | 16:9 输入 |
| --- | --- | --- |
| novice-duality | 768×1024，85152 字节 | 576×1024，67430 字节 |
| novice-blossom | 768×1024，155565 字节 | 576×1024，128636 字节 |
| novice-lighthouse | 1024×768，82049 字节 | 1024×576，58463 字节 |

三个作者均已在此前反馈中曝光，只算回归。两种裁切不是新增独立照片。静态输入不能覆盖手机硬件、运动模糊、变焦、旋转和滤镜全部实况。来源继续保存在 `eval/portrait-novice-sources.json`；用户批注、审查答案没有传给模型。仅进行已授权的 DeepSeek 推理评测，无微调、蒸馏或权重训练。

## 同输入对照

| 案例与画幅 | 正式 v16 | 候选 v21 | 人工核对 |
| --- | --- | --- | --- |
| 明暗近景，两种画幅 | 保持原片、直接拍 | 保持原片、直接拍 | 均保留明暗与神态，符合用户此前意见 |
| 花树持花，两种画幅 | 直接拍，称花枝形成框景 | 指出花枝压头发，降低手机位置后复看 | v21 覆盖用户要求；未把头发重叠夸成遮眼，没有执行后照片，不能证明成片改善 |
| 海边，4:3 | 左转镜头，增加视线留白 | 左转镜头，增加视线留白 | v21 称人物贴边，但脸中心 x=.50、头框 x=.44–.57，文字与数字矛盾；v16 理由还写向右，实际控制器输出向左 |
| 海边，16:9 | 下压镜头，减少头顶留白 | 左转镜头，增加视线留白 | v16 调整类型符合用户此前选择，但裁切不同，不计新盲测胜出；v21 仍虚构贴边，脸中心 x=.50 |

居中不必然意味着视线留白已经最佳，但不能用“贴近边缘”这个错误事实为调整背书。方向计算正确，不代表动作需求判断正确。v21 此轮没有要求放松肩膀，却仍未达到可靠指导标准。

花枝的两次观察框不同，控制器根据当前画面重新计算降低手机，没有复用原图坐标。框来自模型，并非人工地面真值；方向只作小步试探，下一帧必须复看。
