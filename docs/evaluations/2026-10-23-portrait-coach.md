# 出片指导 v10：交付与评测记录

日期：2026-10-23。结论：摄影窗口中的出片流程、双角色动作、会话和拍照状态已实现并通过工程检查；真实模型指导比原构图教练更具体，但尚不能称为“最好”或通过摄影准确性验收。真人盲选与实拍效果未验证。

## 当前使用方式

在摄影窗口点“普通 / 出片”切换，PRO 可同时使用。出片模式先给拍法和理由，再给摄影师或模特一个主要动作。每次指导可比较上次与当前取景；拍下后暂停，点“换个拍法”才开启下一方案。建议和拍法显示在取景框外。

使用保存的官方 DeepSeek 连接，固定 deepseek-flash，不把其他服务的密钥传给 DeepSeek。流程为当前帧观察、拍法与动作生成、程序执行检查；不支持的动作最多请求模型修正一次。观察与导演分开，导演不能覆盖观察到的可见部位、物件和可达性。

没有微调、蒸馏、教师答案训练或任何权重修改。公开原图只保存在忽略的本地研究目录，不进入应用资源；用户明确授权本轮公开案例传给 DeepSeek 用于看图、指导与对比评测。没有打包 APK。

## 逐图核对发现及修正

此前开发轮出现把纹理背景猜成墙、跨拼图组合现场、让站立模特搭手到脚下地面、景别未达到就提醒拍摄。已增加单帧观察、拼图门控、可达性/物件用途、姿态和目标景别检查。

v7 首次保留集发现严重现场错误：模特站在矮石柱上，仍建议朝镜头迈步。v8 加入脚下承托面观察；只有明确 `level_ground` 且落脚处清楚才允许模特走动。该案例回归改为摄影师调整景别。此错误不能从最初保留集成绩中删去。

v8 还出现让模特看向身后的纹理背景，以及将回眸误说成视线离开镜头。v9 增加视线观察与提示约束，程序拒绝把 backdrop 当视线目标，并可请求一次修正。

v9 仍有这些真实局限，未据此宣称达到“零硬错误”的晋级条件：

- `mpp-street-20 / first` 对柱廊横线位置的描述不可靠；降低机位的实际收益需要新画面验证。
- `osborne-window-b-single / alternate` 的计划写了放下手臂，当步却只让摄影师横移；检查目标包含手臂不再遮挡，单靠该动作不能保证。程序能约束动作类型，尚不能充分审查自由文本里的物理因果。
- `pye-parking-11 / alternate` 使用一整片灌木作为转脸参照，缺少明确落点，方向仍可能含糊。
- 部分方案仍偏向横移、走近或改变视线；“树干变前景”“更松弛”等预期不能只凭原图当作已经实现。表情偏好也需要用户选择。

上述是本次助手对图片与输出的核对，不是摄影师独立评分。真人实拍、低照度、更多肤色体型、无人物/多人实际图像、长时间连续指导的覆盖仍不足；无人物、多人、隐藏部位和重复动作目前主要由确定性测试覆盖。

### v10 最后一轮修正和核对

补充了通用约束：只写确定可见的依据；检查目标必须是当前动作能改变的关系；模糊的一整片背景不能当作转脸参照。旧回归中，交叉手臂不再被自动当成问题，相关换拍法改为侧转身体，检查肩线和脸部，未再承诺摄影师横移能让模特放下手。

v10 的确认组共 20 条请求、36 次 HTTP 调用、0 API 错误，估算 ¥0.205138。新男性模特子组 10 条中，4 条拼图请求全部要求单张；3 张单幅的首次请求均提醒拍摄、另外 3 条给身体侧转或摄影师横移。其动作不依赖隐藏的脚部，也未要求新道具。三张单幅来自同一张接触表，不能当三个独立人物样本。

仍未达到零硬错误：柱廊案例仍出现不可靠的横线位置与降低机位效果描述；灌木案例仍给出位置不明确的转脸参照，并推测了未证实的仰卧姿势。新增男性正站图也把一手搭胯概括成双手垂放。提示约束不能保证模型完全遵守，核心程序也尚不能理解所有自由文案的物理含义。这些已记录为失败，未拿正常返回数替代准确率；不继续重复同一批图片来制造更好看的成绩。

男性案例的首次预处理因调用旧版 PowerShell 的脚本策略失败，评测在缺少裁切文件处停止；随后用当前已可执行的 PowerShell 运行原预处理脚本并续跑，只补齐未完成请求。该过程未更改系统脚本策略，也没有重发已保存的成功请求。

## 工程验证

- 69 项 Node 测试通过，覆盖普通教练、出片协议/API、语音和伙伴迁移；其中出片协议/API 38 项。
- Web 资源构建成功；没有 Android 打包。
- 最终浏览器出片检查通过：27 个普通布局、54 个出片布局，包含 4:3、16:9、1:1、横竖屏、安全区域和 PRO。
- 缺 DeepSeek 配置时不调用其他服务，不暴露凭据；观察/导演两阶段都支持旧请求取消。
- 拍照失败不标为已拍，支持重试；原图拍摄重开相机和几何变化保留拍后暂停。
- 已复现并修复异步拍照跨会话问题：普通模式照片完成不能把新出片会话标成已拍，旧照片也不能覆盖“换个拍法”。浏览器先出现失败断言，修正后通过。
- 现有语音设置、男女声请求、取消、失败提示与保存/取消回归通过。
- 最终只读代码复核：两处最后修正通过，未发现新的重要工程问题。这不替代模型摄影质量验收。
